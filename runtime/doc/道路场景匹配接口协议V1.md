# 道路场景匹配服务接口协议（V1）

> 版本：v1.2 · 更新日期：2026-07-24  
> 适用接口：`/api/test/highway_road_match`

---

## 1. 基本信息

| 项目 | 值 |
|------|-----|
| Base URL | `http://<host>:19000` |
| 请求方法 | `POST` |
| 请求格式 | `multipart/form-data` |
| 接口路径 | `/api/test/highway_road_match` |
| 主要用途 | 客户端上传相机 ID 和图片；服务端进行道路 IoU 与 Hybrid 特征匹配，并返回匹配图片对应的多组 Y 坐标和距离 |

---

## 2. 业务逻辑

1. 客户端上传 `camera_id` 和一张待匹配图片。
2. 服务端读取场景图库目录：`/opt/RoadSegmentTestService/scene/<camera_id>/`。
3. 道路匹配流程：
   - 对客户端图片调用道路分割接口，得到道路多边形。
   - 对该相机目录下的候选图片调用道路分割接口，得到候选图道路多边形。
   - 将客户端多边形和候选图多边形栅格化后计算 IoU：`intersection / union`。
   - 选择 IoU 最高的候选图片；最高分不低于道路阈值时，读取输入端为该图片定义的 `result`。
4. 特征匹配流程：
   - DINOv3 对全部场景候选图片进行粗排。
   - LoMa 对 DINOv3 Top-2 候选进行局部特征和几何匹配。
   - 选择综合得分最高的图片，读取输入端为该图片定义的 `result`。
   - 场景候选图片特征按照文件修改时间和文件大小缓存；文件变化后自动重新计算。
5. 最终判定：
   - `road_result` 与 `feature_result` 相同，且均为 `1` 或 `2`：`agreed=true`，最终 `result` 返回相同类别，允许上报。
   - 两种算法结果不同，或道路结果为 `0`：`agreed=false`，最终 `result=0`，不予上报。
   - 特征服务调用失败时，接口返回 HTTP 500，不产生有效上报结果。
6. 图片坐标及距离信息：
   - 匹配成功后，根据 `best_image` 读取相机目录下的 `distance_map.json`。
   - 返回该基准图片对应的 `distances` 数组。
   - 未配置时返回空数组。

最终逻辑可以表示为：

```text
if road_result in {"1", "2"} and road_result == feature_result:
    agreed = true
    result = road_result
else:
    agreed = false
    result = "0"
```

## 3. 请求格式

### 3.1 multipart 字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `data` | string(JSON) 或 JSON 文件 | 是 | 请求元数据 |
| `image` | file | 是 | 客户端上传的待匹配图片 |

### 3.2 `data` 字段

```json
{
  "camera_id": "9610",
  "data_format": "binary",
  "threshold": 0.3
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `camera_id` | string | 是 | 相机 ID，对应场景图库目录 `/opt/RoadSegmentTestService/scene/<camera_id>/` |
| `cameraId` | string | 否 | `camera_id` 的兼容字段；同时存在时优先使用 `camera_id` |
| `data_format` | string | 否 | 当前建议固定传 `binary` |
| `threshold` | number | 否 | 本次请求使用的匹配阈值；不传时使用服务配置 `MATCH_THRESHOLD` |

### 3.3 场景图库命名约定

候选图片放在：

```text
/opt/RoadSegmentTestService/scene/<camera_id>/
```

示例：

```text
/opt/RoadSegmentTestService/scene/9610/1_preset_06_preset.jpg
/opt/RoadSegmentTestService/scene/9610/2_preset_06_right.jpg
```

道路匹配和 Hybrid 特征匹配都使用该相机目录中的全部场景候选图片。`result` 和 `direction` 由图片输入端上传时定义，不再依赖图片文件名。

| 返回值 | 含义 |
|------|------|
| `0` | 由输入端定义 |
| `1` | 由输入端定义 |
| `2` | 由输入端定义 |

## 4. 成功响应

### 4.1 响应示例

```json
{
  "status_code": 200,
  "msg": null,
  "data": {
    "camera_id": "9610",
    "result": "1",
    "best_image": "1_preset_02_down.jpg",
    "total_score": 0.9568,
    "direction": "向上上行、向下下行",
    "distances": [
      {"y": 520, "distance": 50},
      {"y": 680, "distance": 30},
      {"y": 840, "distance": 15}
    ]
  }
}
```

### 4.2 `data` 返回字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `camera_id` | string | 请求中的相机 ID |
| `result` | string | 最终联合结果：两种算法一致时为 `1` / `2`，否则为 `0` |
| `best_image` | string/null | 最终最佳匹配图片名称 |
| `total_score` | number | 最终综合匹配分数，范围 `[0,1]` |
| `direction` | string/null | 匹配图片的行驶方向：`向上上行、向下下行` 或 `向上下行、向下上行` |
| `distances` | array | 该基准图片对应的距离信息 |
| `distances[].y` | number | 基准图片中的 Y 坐标 |
| `distances[].distance` | number | Y 坐标代表的距离，单位米 |

---

## 5. 错误响应

### 5.1 统一格式

```json
{
  "status_code": 400,
  "data": null,
  "msg": "错误信息"
}
```

### 5.2 常见错误

| HTTP | 场景 |
|------|------|
| 400 | 缺少 `data`、缺少 `camera_id`、缺少上传图片、`camera_id` 非法 |
| 404 | `/opt/RoadSegmentTestService/scene/<camera_id>/` 不存在或目录下没有候选图片 |
| 422 | 上传图片无法解码或图片格式无效 |
| 500 | 调用道路分割接口失败、特征服务失败、模型推理失败或服务内部异常 |

## 6. 调用示例

```bash
curl -X POST "http://<host>:19000/api/test/highway_road_match" \
  -F 'data={"camera_id":"9610","data_format":"binary","threshold":0.3}' \
  -F "image=@client.jpg"
```

也可以使用 JSON 文件：

```bash
curl -X POST "http://<host>:19000/api/test/highway_road_match" \
  -F "data=@match_data.json" \
  -F "image=@client.jpg"
```

`match_data.json`：

```json
{
  "camera_id": "9610",
  "data_format": "binary",
  "threshold": 0.3
}
```

未配置图片距离信息时：

```json
{
  "best_image": "1_preset_02_down.jpg",
  "total_score": 0.9568,
  "direction": null,
  "distances": []
}
```

## 7. 服务配置

配置文件：

```text
/opt/RoadSegmentTestService/RoadSegmentTestService.conf
```

关键配置：

```text
EVENT_TEST_PORT=19000
ROAD_SEGMENT_URL=http://127.0.0.1:8990/api/extract_road
FEATURE_SERVICE_URL=http://127.0.0.1:19001/match
SCENE_ROOT=/opt/RoadSegmentTestService/scene
RESPONSE_LOG_DIR=/opt/RoadSegmentTestService/logs/responses
MATCH_THRESHOLD=0.30
```

| 配置项 | 说明 |
|------|------|
| `EVENT_TEST_PORT` | 当前服务监听端口 |
| `ROAD_SEGMENT_URL` | 道路分割后端接口地址 |
| `FEATURE_SERVICE_URL` | DINOv3 特征匹配服务地址 |
| `SCENE_ROOT` | 场景图库根目录 |
| `RESPONSE_LOG_DIR` | 每次业务接口响应的独立 JSON 归档根目录 |
| `MATCH_THRESHOLD` | 默认匹配阈值 |

修改配置后需要重启服务：

```bash
/opt/RoadSegmentTestService/startRoadSegmentTestService restart
```

Hybrid 特征服务由 systemd 管理：

```bash
systemctl status road-segment-feature.service
systemctl restart road-segment-feature.service
journalctl -u road-segment-feature.service -f
```

特征服务仅监听目标机回环地址：

```text
http://127.0.0.1:19001
```

健康检查：

```bash
curl http://127.0.0.1:19001/ping
```

模型文件：

```text
/opt/RoadSegmentTestService/models/vit_base_patch16_dinov3.lvd1689m/model.safetensors
```

## 8. 日志

业务日志：

```text
/opt/RoadSegmentTestService/logs/road_segment_test_service.log
```

每次业务接口响应会单独保存为 JSON 文件，包括成功响应和错误响应：

```text
/opt/RoadSegmentTestService/logs/responses/YYYYMMDD/
```

文件名格式：

```text
<接口名>_<Unix毫秒时间戳>_<进程内序号>.json
```

示例：

```text
highway_road_match_1784800000123_7.json
highway_road_segment_1784800000456_8.json
```

响应归档写入失败只记录错误日志，不改变原接口响应。

运维脚本日志：

```text
/opt/RoadSegmentTestService/bash.start.log
```

匹配请求会记录：

- `camera_id`
- 使用的阈值
- 最佳匹配图片
- 最佳得分
- 道路匹配类别
- Hybrid 特征匹配类别
- 两种算法是否一致
- 比较图片数量
- 失败图片数量
- 请求耗时

联合判断日志示例：

```text
match request done camera_id=9610 result=1 road_result=1 feature_result=1 agreed=true ...
```
